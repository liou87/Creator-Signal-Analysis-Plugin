## 范围类

### D-00 平台选 B 站，指数选商业化程度

- **选项**：B 站 / YouTube / 小红书 / X；商业化程度 / 公开求助意愿 / 两个都做
- **选择**：B 站 + 商业化程度，只做一个指数
- **理由**：B 站空间页不登录即可访问，公开信息丰富。商业化程度的证据是客观的、能在页面上指给人看的（广告声明、购物链接、付费入口）；求助意愿依赖语义判断，更难辩护。做深一个比做浅两个更能讲清楚。
- **代价**：不覆盖需求里的另一个示例信号。

### D-01 分数给谁用

- **质疑**：没有使用者和决策场景，任何权重都无从辩护。
- **选项**：线索筛选 / 品牌方选达人 / 观众判断可信度 / 不绑定场景
- **选择**：线索筛选
- **理由**：需求举的两个例子（商业化程度、公开求助意愿）合起来是「有没有生意、有没有需求」，是线索评分的结构。**这是推断，不是需求明说的。**
- **影响**：所有变现方式都计入，包括创作者卖自己的周边和课程。
- **代价**：不区分合作品牌的品类，不适合直接拿去做品牌选达人。如果场景是「观众判断可信度」，分数的含义会完全不同（披露越规范反而越可信）。

## 评分类

### D-02 两层用加法合成

- **质疑**：强度和广度相加，同样 50 分可能是完全不同的两种人。
- **选项**：加法 / 几何平均 / 不合成只给两个分
- **选择**：加法，两个子分始终并列展示
- **理由**：变现渠道互为替代，应允许补偿。几何平均会把单渠道创作者压到接近 0。需求明确要「一个指数」，不合成有答非所问的风险。
- **代价**：单个数字有信息损失，靠分数拆解弥补。

### D-03 占比用收缩估计

- **质疑**：发 3 条视频有 2 条广告，占比 67%，直接满分？
- **选项**：原始占比 / 绝对条数 / 收缩估计
- **选择**：`r̂ = Σw / (n + 5)`
- **理由**：样本少时向 0 收缩。3 条 2 广告 → 0.25；30 条 10 广告 → 0.29。绝对条数则会惩罚更新慢的人。
- **代价**：多一个参数；低产创作者被系统性压低。

### D-04 取样窗口

- **质疑**：取最近 30 条，日更的人是一个月，月更的人是两年半。
- **选择**：最近 30 条且 12 个月内，报告写明覆盖时间段
- **代价**：低产者样本更少，由 D-03 和置信度兜底。

### D-05 封顶值来自样本分位数

- **质疑**：占比 0.5 即满分，这个 0.5 哪来的？
- **选择**：初值 0.5，校准后换成样本 r̂ 的 90 分位数
- **理由**：这是纯统计，不需要人工判断。参照新榜指数用基准常数做标准化的做法。
- **代价**：二十个样本的 90 分位数不稳定，如实说明。

### D-06 疑似档权重保留先验 0.5

- **质疑**：0.5 哪来的？
- **选项**：固定折扣 / 用标注集上的实测精确率
- **选择**：保留 0.5，不确定性由区间承担
- **理由**：理想做法是实测精确率（「判为疑似时真是商业内容的概率」）。但判断软广需要行业经验，本项目的标注者明确表示不具备。让非专业者硬标，得到的数字比先验更误导人。
- **代价**：点估计里仍有一个没有依据的数；区间可能较宽。
- **备注**：这是最初方案被推翻的地方。最初打算用实测精确率，讨论后改为现在的做法。

### D-07 账号层只分强弱两级

- **质疑**：10/10/5/5/5/5 凭什么？
- **选项**：等权 / 专家赋权 / 数据拟合
- **选择**：两级（2 : 1），只主张顺序不主张比例
- **理由**：样本不够做数据拟合。顺序的依据是「商业意图的明确程度」。
- **代价**：仍是先验。用敏感性分析（权重 ±20%、60/40 换成 50/50 和 70/30）证明排序对它不敏感。

### D-08 疑似档必须有行动引导

- **质疑**：测评区人人都提品牌，「品牌 + 推荐话术」会大面积误报。
- **选择**：必须出现行动引导（专属福利、限时、去哪买）；「品牌方提供样品」单列为披露
- **代价**：召回率下降。

### D-15 三档加区间

- **质疑**：0–100 分五档，精度装得太高。58 和 62 有什么区别？
- **选项**：单个分数五档 / 分数加区间三档 / 两个子分不合成
- **选择**：分数 + 区间 + 低中高三档
- **理由**：区间下界只算确证、上界把疑似全算上，直接回应「分数只是下界」这个局限。校准样本支撑不了五档的分辨率。
- **代价**：界面更复杂。

## 分类类

### D-09 关键词误判

- **质疑**：「这期不是恰饭」；专门讲广告行业的视频。
- **选择**：否定模式排除 + 有模型时复核；证据原文展示给用户自行判断
- **代价**：无模型时仍有误报，用实测精确率说明。
- **已被 D-23 部分取代**：「有模型时复核」没有实现，原因见 D-23。

### D-10 大模型只分类、不出分，且影响有上界

- **质疑**：模型不稳定，同一个人跑两次分数不同。
- **选项**：模型直接打分 / 纯关键词 / 规则出分 + 模型分类
- **选择**：规则出分 + 模型分类。A、B 两档只由规则判定，模型只能影响 C 档。
- **理由**：模型直接打分不可复现，也说不出计算方式，与验收要求冲突。纯关键词对软广的召回低。现在的做法下，模型对总分的最大影响是可以算出来的。
- **配套**：temperature 0；按内容哈希缓存；每条证据标注来源是规则还是模型。
- **代价**：软广识别完全依赖模型；没有 API Key 时退化为关键词组合。

### D-11 提示注入

- **质疑**：视频简介是不可信输入，可以写「忽略以上指令」。
- **选择**：模型输出限定为枚举值；引用必须是原文子串，否则整条丢弃；加上 D-10 的影响上界
- **理由**：即使注入成功，最坏结果也只是 C 档误判，不会波及 A、B 档。

### D-20 视频简介里的商务联系脚注归账号层

- **发现于**：写规则时。很多创作者在每条视频简介末尾写「商务合作：邮箱」。
- **问题**：如果按披露用语匹配，这类创作者的每一条视频都会被判成广告，内容层直接满分。
- **选择**：规则匹配前先剔除这类脚注；它在两条以上视频里出现时，计入账号层的「商务合作联系方式」
- **理由**：脚注说明账号在接商单，不说明这一条视频是广告。
- **代价**：极少数情况下真正的披露语和脚注写在同一行，会被一起剔除。

### D-21 充电专属内容计入 B 档

- **问题**：B 档的定义是「推荐 + 购买方式」，充电专属视频不是在推荐商品。
- **选择**：计入 B 档，类型标为「粉丝付费」
- **理由**：使用场景是线索筛选（D-01）。视频本身就是付费产品，是确证的变现行为，不需要判断。
- **代价**：B 档的定义被略微扩大。如果场景换成「观众判断可信度」，这一条应当去掉。

### D-22 两种 C 档口径不混用

- **问题**：模型可能只判了一部分视频（漏了几条，或几条的引用没通过校验）。
- **选项**：模型判了的用模型、没判的用关键词 / 整体退回关键词
- **选择**：整体退回关键词，并在报告里注明原因
- **理由**：混用时同一份报告里的 C 档有两种标准，无法解释「为什么这条算、那条不算」。
- **代价**：模型只漏一条也会让整次调用作废。

### D-23 模型不复核 A、B 档（修订 D-09）

- **背景**：D-09 原计划在有模型时让它复核关键词命中，以排除「这期不是恰饭」之类的误判。
- **问题**：这样模型就能推翻 A、B 档的结论，与 D-10「模型只能影响 C 档、对总分的影响有上界」直接冲突。
- **选择**：不做模型复核。否定句只靠规则排除（匹配之前和匹配之内的否定词都检查）。
- **理由**：「模型的影响有上界」是整个方案可解释性的基础，比多排除几个误报更重要。
- **代价**：规则没覆盖到的否定说法会造成误报。靠证据原文展示让使用者自行识别。

## 数据类

### D-12 置顶评论

- **质疑**：只看标题和简介；B 站的带货蓝链主要在置顶评论。
- **选择**：置顶评论列为必须验证的数据源，可行则必做
- **代价**：多一类请求，触发风控的风险上升。

### D-13 「未能检查」单列

- **质疑**：页面结构变了没抓到，和创作者确实没有，是两回事。
- **选择**：账号层指标三态（有 / 无 / 未能检查），未能检查只降置信度不扣分

### D-16 合规边界

- **选择**：只读用户浏览器里已经可见的公开内容；用户手动触发；单人规模；不上传、不持久化创作者数据；发给模型的只有公开文本，并在设置页明示。

### D-17 数据源可行性只能在真实浏览器里验证

- **事实**：2026-11-15 从命令行直接请求 `x/web-interface/view`，返回风控拦截页（非浏览器环境）。
- **结论**：这不能说明浏览器里不可用，只说明无法在开发环境里验证。
- **选择**：在插件里做一个「数据源自检」，在真实页面上逐项报告每个数据源是否可用；提取层为每项数据准备主、备两条路径。

### D-24 接口为主、页面为辅（修订最初计划）

- **最初计划**：优先读页面，因为投稿列表接口有签名和风控。
- **改为**：优先走接口（实现了 WBI 签名），失败时自动退到页面。
- **理由**：
  1. 空间页是前端渲染的，类名随改版变化，按类名抓取最容易坏。
  2. 接口返回结构化数据，有发布时间和完整简介；页面上只有标题，取样窗口（D-04）需要发布时间。
  3. 签名算法是公开的，并且可以用公开算例做单元测试；页面结构没法测。
- **页面备用路径的写法**：不依赖类名。视频列表取所有 `/video/BV…` 链接；入口判断取页面上的短文本。
- **代价**：接口可能触发风控。此时自动退到页面，只能分析当前页面可见的视频，报告的自检里会写明。

### D-27 取不到视频时不给指数

- **发现于**：2026-11-15 第二次真实页面验证。一位有 524 条投稿的创作者，报告显示「样本 0 条 · 15 分 · 商业化程度：低」。
- **问题**：这是设计漏洞，不只是提取的问题。账号层做了「没抓到 ≠ 没有」的三态（D-13），内容层却没有：视频列表取不到时直接按 0 分算，给出一个看起来确定的「低」。
- **选项**：
  1. 照旧给分，靠「置信度：低」提醒
  2. 只给账号层的分数，标注「部分结果」
  3. 不给指数，明确说「未能评估」
- **选择**：3。同时区分视频列表的来源：接口明确返回了投稿但都在窗口之外，才解读为「最近没有投稿」并按 0 计；只从页面读到、或完全没取到，都算未能评估。
- **理由**：内容层占 60 分。缺了它，剩下的数字不足以称为指数；而一个带着「低」字的分数会被当成结论使用，旁边的置信度提示挡不住。
- **代价**：提取不稳定时，使用者会频繁看到「无法给出指数」。这是如实的。
- **配套**：报告同时显示「取到多少条」和「窗口内多少条」，取样窗口不再悄悄吞掉样本；数据来源自检在有失败项时默认展开。

### D-28 不伪造设备指纹来通过风控

- **背景**：B 站对投稿列表接口有风控。公开资料里常见的绕过做法是在请求里附上伪造的设备指纹和鼠标轨迹参数。
- **选择**：不做。只复用平台发给这个浏览器会话的东西：签名密钥（任何访客都能取到）和页面里内嵌的访问令牌。接口仍被拒绝时，退到另一个公开接口，再退到读页面上已经显示的内容。
- **理由**：D-16 的边界是「只读用户浏览器里已经可见的公开内容」。复用页面自己的密钥和令牌，是在做页面本来就会做的请求；伪造指纹是在骗过对方的反自动化检测，性质不同。这条线面试时要能讲清楚。
- **代价**：数据可能取不全。此时如实显示「未能评估」（D-27），并提示使用者切到投稿页或登录后重试。
- **状态**：接口究竟因为什么被拒还没有确认（等自检结果）。如果确认只有伪造指纹才能通过，本决定不变，改为以读页面为主。

### D-29 「未能检查」的账号层指标计入区间上界

- **发现于**：2026-11-15 第三次真实页面验证。报告显示「24 分 · 区间 24–24 · 低」，而账号层有三项因为读不到简介而未能检查，合计 20 分。
- **问题**：区间原先只反映疑似软广的不确定性。未能检查的项按 0 分算进了点估计，区间却收缩成一个点，显得比实际知道的更确定。真实分数可能在 24 到 44 之间，跨了「低」和「中」。
- **选项**：
  1. 维持原样，靠置信度提示
  2. 未能检查的项按一半分值计入点估计
  3. 点估计不变，上界加上未能检查的项的全部分值
- **选择**：3。并在区间跨档时明说「还不能确定属于哪一档」。
- **理由**：区间的含义统一为「从只算已确认的，到不确定的全部成立」。选项 2 是在没有依据的情况下猜一个中间值。
- **代价**：数据取不全时区间会很宽。这是如实的。

### D-30 商品链接按链接形态识别，不看平台的附加字段

- **发现于**：同一次验证。7 条命中里有 1 条误报，引用是 `Akira` —— 平台给评论里的热词自动加的搜索链接。
- **原因**：我原先判断「是不是商品链接」的依据是链接的附加信息里有没有 goods 字样。这是凭印象猜的字段含义，实际上所有链接都带这类字段，包括搜索词。
- **选择**：
  1. 只按链接地址的形态识别：`b23.tv/mall-`（商品）、`b23.tv/cm-`（商业推广）以及已知购物网站。这两种短链形态来自真实页面上的 6 条命中。
  2. 附加字段只读一个：`is_word_search` 为真的是平台自动加的搜索词，排除。
  3. 自检里输出链接的原始样例，下次可以核对对字段的理解。
- **理由**：地址形态是看得见、能解释的；附加字段的含义没有文档，猜错了也不容易发现（这次是靠人眼看引用发现的）。
- **代价**：平台换了短链形态就会漏判。漏判方向与「宁可低估」一致。
- **同时修正**：类型标注。原先命中的全标成「品牌合作」，但商品短链分不清是自营还是分销，改标「商品带货」；只有商业推广短链才标「品牌合作」。
- **教训**：证据列表里展示原文引用（D-11 的要求）这次起了作用 —— 误报是因为引用一眼看上去就不对才被发现的。

### D-31 充电：页面上没看到不能说「无」

- **发现于**：同一次验证，报告显示「充电：无」。
- **问题**：D-13 的原则是「认出了导航栏，才敢说某个入口没有」。这对小店和课程成立，因为它们是导航栏里的标签。充电是页头的按钮，不在导航栏里，同样的推理不适用。
- **选择**：充电只有接口明确返回时才有「无」；页面上看到按钮算「有」，没看到算「未能检查」。
- **代价**：账号信息接口被风控拒绝时，充电多数情况下是「未能检查」。

### D-32 视频列表和账号信息的接口顺序按验证结果调整

- **验证结果**：`arc/search` 和 `acc/info` 都被风控拒绝（-352）；`recArchivesByKeywords` 未登录可用，按发布时间从新到旧返回。
- **选择**：视频列表以 `recArchivesByKeywords` 为主，`arc/search` 降为备用。账号信息在 `acc/info` 之后增加名片接口 `web-interface/card`，去掉从页面描述信息读简介的路径（验证发现描述信息里没有简介）。
- **未验证**：名片接口是否可用。

### D-33 视频列表：后台加载投稿页；降低请求密度

- **发现于**：2026-11-16 第四次验证。前一天成功的 `recArchivesByKeywords` 返回 HTTP 412；`arc/search` 四次验证全部 -352。视频列表退到读主页上的链接，拿到的不是最近投稿。
- **问题**：视频列表是内容层的输入，却没有一条稳定的路径。
- **选项**：
  1. 伪造设备指纹让 `arc/search` 通过 —— D-28 已排除
  2. 提示使用者手动切到「投稿」标签再分析
  3. 在后台加载投稿页，读它渲染出来的视频链接
- **选择**：3，并保留 2 作为它失败时的提示。当前就在投稿页时直接读，不再加载。
- **理由**：投稿页的请求由 B 站自己的页面代码发出，插件只读渲染结果，得到的内容和使用者自己点一下「投稿」看到的相同。它不依赖任何一个可能被拦的接口。演示时不需要额外的手动步骤。
- **对 D-16 的影响**：边界从「浏览器里已经可见的公开内容」放宽为「使用者点一下就能看到的公开内容」。仍然是公开内容、手动触发、不伪造参数。
- **代价**：多加载一个页面，分析会慢几秒；这条路径还没有在真实页面上验证过。
- **同时**：
  - 移除 `arc/search`。它从未成功过，每次尝试只是多一个被拒的请求。
  - 不再请求视频标签。两次验证共 60 条视频，标签没有贡献任何证据，却占了三分之一的请求量。代价是带「恰饭」之类标签而正文没写的视频会漏掉。
  - 并发从 3 降到 2，每条视频之间停顿 150 毫秒。
- **没有依据的部分**：412 是否由请求量引起，并不清楚。降低请求密度是出于谨慎，不是因为确认了因果。

### D-34 平台标记作为证据；充电专属视频说明充电已开通

- **发现于**：同一次验证。「充电专属」那条证据的引用是「充电专属143.4万1.6万02:1」—— 封面角标的文字混进了乱码标题，规则碰巧匹配上。
- **问题**：结论是对的，依据是错的。标题修正之后这条证据会消失，除非有正当的来源。
- **选择**：从详情接口读平台对视频的标记，以平台显示的文字（「充电专属」）作为一个独立的文本字段进入规则。报告里字段显示为「平台标记」。
- **与约束 4（引用必须是原文子串）的关系**：平台标记是结构化事实，没有「原文」。这里用平台自己在封面上显示的那几个字作为引用，使用者在页面上能看到同样的字。
- **推论**：样本里有充电专属视频时，账号层的「充电」直接判「有」。这不需要接口，也不可能错。
- **重复计分**：这条视频在内容层算一条确证，充电在账号层算 5 分。两层回答的是不同的问题（多频繁、有哪些渠道），与「视频里挂了店铺链接、账号也开了小店」同理。
- **未确认**：接口里的字段名来自公开资料。自检会报告命中条数；若为 0 而页面上明显有充电专属视频，说明字段名不对。

### D-35 充电专属视频该怎么计分

- **发现于**：2026-11-16 第五次验证。12 条确证里有 6 条是充电专属，内容层的 41 分里约一半来自它。
- **问题**：D-21 把充电专属计入 B 档时，没有预料到它会占这么大比重。面试官会问：付费内容和带货广告是一回事吗？报告里它还被标成「带货转化」，名不副实。
- **选项**：
  1. 维持现状：与带货链接同等计分。理由是线索筛选看的是「有没有在变现」，付费内容是最直接的变现。
  2. 仍按确证计分，但把 B 档改名为「直接变现」，下分「带货」和「付费内容」两类，名实相符。
  3. 充电专属不计入内容层，只在账号层体现为「充电：有」。理由是它面向粉丝，不是商业合作。
- **选择**：2（使用者于 2026-11-16 确定）。
- **理由**：在线索筛选场景下（D-01），一个把五分之一的视频做成付费内容的创作者确实在认真经营，不计入会低估。选项 3 的折中做法（打折计入）会引入又一个没有依据的折扣数，没有采用。
- **做法**：B 档由「带货转化」改名为「直接变现」。报告在样本说明里列出确证的构成，例如「确证 12 条（带货 6、付费内容 6）」。
- **代价**：如果使用场景换成「品牌方选达人」，付费内容不该和广告带货同等计分，这一条要重新考虑。

### D-25 模型接口的访问权限按地址单独申请

- **选项**：安装时申请所有网站的访问权限 / 用户保存设置时只申请填写的那个地址
- **选择**：后者
- **理由**：插件默认只能访问 B 站的两个域名。「可访问所有网站」的权限对一个只分析 B 站的工具来说说不过去。

### D-26 置信度规则

- **选择**：样本少于 10 条为低；有「未能检查」的账号层指标为中；否则为高。没用模型只提示、不降级。
- **理由**：置信度只回答「数据够不够」。没用模型影响的是区间上界，下界（确证部分）不受影响。
- **代价**：10 条这个阈值是先验的。

## 验证类

### D-14 校准不依赖专业判断

- **质疑**：自己设计规则又自己标注，是循环论证。而且标注者不是领域专家。
- **选项**：自己凭感觉标 / 找第二人 / 改变验证方式
- **选择**：
  1. 只标可观察的事实（有没有购买链接、有没有广告声明），不标主观判断
  2. 用两组极端样本检验区分度，代替人工排序
  3. 模型作为第二标注者，只人工复核规则与模型不一致的条目
- **代价**：C 档无法验证；模型一致性不等于准确率；只能证明分得开两头。
