# 架构

## 数据流

```
B 站空间页
   │  内容脚本读取页面 + 请求公开接口
   ▼
CreatorSnapshot        创作者快照：账号信息 + 视频列表（标题、简介、标签、置顶评论）
   │  classify：规则（必有） + 模型（可选）
   ▼
Evidence[]             证据：哪条视频、哪一档、什么类型、原文引用、来源
   │  score：纯函数
   ▼
Report                 分数、区间、分档、子分、拆解、置信度
   │
   ▼
侧边栏界面
```

三个数据结构是模块之间唯一的接口。每一步只依赖上一步的输出。

## 模块

| 目录 | 职责 | 依赖浏览器 |
|---|---|---|
| `src/extract/` | 从 B 站页面和接口取数据，产出 `CreatorSnapshot` | 是 |
| `src/classify/` | `rules.ts` 关键词与正则；`llm.ts` 模型分类。产出 `Evidence[]` | 仅 `llm.ts` 需要网络 |
| `src/scoring/` | `score(snapshot, evidence) → Report`。参数全部在 `config.ts` | **否，纯函数** |
| `src/ui/` | 侧边栏：发起分析、进度、报告 | 是 |
| `src/pipeline.ts` | 侧边栏一侧的流程编排：提取 → 取样 → 分类 → 评分 | 是 |
| `entrypoints/` | 插件入口：后台脚本（只负责打开侧边栏）、内容脚本、侧边栏 | 是 |

评分引擎不依赖浏览器，是为了能用单元测试验证单调性、边界和可复现性，也方便校准时离线批量重算。

## 数据来源

提取在内容脚本里进行，请求带着空间页自己的上下文。接口为主、页面为辅（D-24）。

**下表的「验证结果」一列全部为未验证。** 开发环境直接请求 B 站接口会被风控拦截（D-17），接口路径和字段来自公开资料。每次分析时，提取层把每条路径是否走通记进 `CreatorSnapshot.sources`，报告底部的「数据来源自检」原样展示。在真实页面上跑过之后，把结果填回这张表。

| 数据 | 主路径 | 备用路径 | 验证结果 |
|---|---|---|---|
「验证结果」一列截至 2026-11-15，均为未登录状态。

| 数据 | 主路径 | 备用路径 | 验证结果 |
|---|---|---|---|
| 签名密钥 | `x/web-interface/nav`（未登录也返回） | 无；取不到则所有签名接口跳过 | **可用** |
| 创作者 UID | 标签页地址（`src/extract/identify.ts`） | 无 | **可用**。地址里 UID 前可能有语言前缀 |
| 昵称、简介、认证 | `x/space/wbi/acc/info`（需签名） | `x/web-interface/card`；昵称再退到页面标题 | 主路径**不稳定**：成功过一次，被拒过两次（-352）。名片接口**可用**，但不含充电信息 |
| 视频列表 | 接口 recArchivesByKeywords（不需签名） | 投稿页（当前就在投稿页则直接读，否则后台加载）；再退到当前页面上的视频链接 | 接口**不稳定**：成功 1 次，HTTP 412 两次。后台加载投稿页**成功 1 次**，取到的 30 条与接口当初返回的时间范围一致。当前页面链接可用，但主页上的不是最近投稿 |
| 视频标题、简介、发布时间 | `x/web-interface/view` | 无 | **可用**，两次均 30/30。标题以它为准 |
| 充电专属标记 | view 返回里的 is_upower_exclusive | 无 | **已确认**：30 条里标出 6 条，标题与页面上带充电专属角标的视频相符 |
| 置顶评论 | `x/v2/reply/wbi/main`（需签名） | `x/v2/reply/main`，再退到 `x/v2/reply` | 主路径**可用**，30/30 |
| 评论里的链接 | 评论返回里的 `jump_url`：片段、跳转地址、是否为搜索词 | 无 | 片段和地址**可用**。`is_word_search` 字段的含义待下次自检里的原始样例确认 |
| 充电 | `acc/info` 返回里的 `elec.show_info.show` | 页面上有「充电」按钮算「有」；样本里有充电专属视频算「有」；否则「未能检查」 | 字段名是推测，未确认 |
| 小店、课程入口 | 页面导航栏里是否有「小店 / 橱窗」「课堂 / 课程」标签 | 无 | 导航栏能认出。**还没有在开了小店或课程的创作者页面上确认过确实有对应标签** |

几个设计点：

- **WBI 签名**（`src/extract/wbi.ts`）是纯函数，用公开文档里的算例做了单元测试，算法本身是确认过的。
- **页面文字判断不依赖类名。** 收集页面上所有 8 个字以内的短文本，看有没有对应入口。只有认出了导航栏（「主页」「动态」「投稿」等）才敢说某个入口「无」，否则记为「未能检查」（D-13）。
- **限流**：单条视频的详情请求并发为 3，一次分析最多 30 条视频、约 90 个请求。
- **提取层只记录事实**，不做判断。例如置顶评论里的链接，提取层只记「这个片段是链接、平台是否标为商品」，算不算带货由分类层决定。

## 真实页面验证记录

每次在真实浏览器里验证后追加一条：看到了什么、与假设哪里不符、怎么改的。

### 2026-11-15 第一次：侧边栏认不出创作者

- **现象**：在 `space.bilibili.com/zh-Hans/447317111?spm_id_from=…`（未登录）打开侧边栏，提示「请在空间页打开本面板」；点「重新检测」没有任何变化。
- **原因**：识别规则假定域名后紧跟数字 UID。实际地址在 UID 前有一段语言前缀 `/zh-Hans/`。
- **修正**：
  1. 识别规则允许一段可选的语言前缀，并要求 UID 之后是路径分隔符或结尾，避免把路径里别处的数字当成 UID。
  2. 侧边栏和内容脚本原先各写了一份识别规则，合并为 `src/extract/identify.ts` 一处。
  3. 「重新检测」无论结果如何都显示带时间的反馈。
- **教训**：对页面地址和结构的假设在看到真实页面之前都不可靠。这次的问题发生在提取开始之前，所以数据来源自检没能帮上忙 —— 自检只覆盖了「提取过程」，没有覆盖「识别创作者」这一步。
- **从截图里额外确认的**：导航栏文字为「主页 / 动态 / 投稿 524 / 合集和系列 / 追番追剧」，与入口判断里用来认导航栏的词一致；个人简介里有「商务合作请联系vx：…」，与商务联系方式规则的写法一致。页头横幅图片里的「关注公众号」「小卖部」是图片上的字，读不到，属于已知局限。

### 2026-11-15 第二次：取到 0 条视频，却给出了「15 分 · 低」

- **现象**：同一页面（未登录，停在「主页」标签），识别创作者成功。报告显示样本 0 条、内容层 0、账号层 15（商务联系方式 + 充电）、总分 15、商业化程度低。这位创作者有 524 条投稿。
- **已知**：简介读到了，说明账号信息这一步走通了（接口或页面备用路径之一）。
- **未知**：视频列表是哪条路径失败的。当时自检是折叠的，没有看到。最可能的情况是投稿列表接口被拒，退到读页面，而主页上显示的是几条发布很早的代表作，全部落在 12 个月窗口之外。**这是推测。**
- **修正**：
  1. 设计漏洞：内容层取不到时不再按 0 分给出指数，而是显示「未能评估」（D-27）。
  2. 报告同时显示「取到多少条」和「窗口内多少条」。
  3. 自检在有失败项或未能评估时默认展开；每条路径的详情里写明取到的视频的发布时间范围。
  4. 视频列表增加一条备用接口；主接口带上页面内嵌的访问令牌。
  5. 明确不伪造设备指纹（D-28）。
- **待确认**：重新运行后，根据自检里每条路径的返回码决定下一步。

### 2026-11-15 第三次：第一份有内容层证据的报告

另一位创作者（UID 39627524，未登录）。自检完整可见。

- **走通的**：视频列表（备用接口，最近 100 条）、视频简介 30/30、标签 30/30、置顶评论 30/30（其中 20 条有置顶评论）。
- **没走通的**：`acc/info` 和 `arc/search` 都返回 -352 风控校验失败；从页面描述信息读简介，格式不符（描述信息里根本没有简介）。
- **结果**：样本 30 条，命中 7 条，**全部来自置顶评论**，标题和简介里一条都没有。这是 D-12「带货链接主要在置顶评论」的第一个实证。
- **发现的问题与修正**：
  1. 一条误报（引用是平台自动加的搜索词）。识别商品链接的方法是错的，已改（D-30）。
  2. 区间显示 24–24，而账号层有 20 分未能检查。已改为计入上界（D-29）。
  3. 充电显示「无」，没有依据。已改（D-31）。
  4. 命中类型全标「品牌合作」，过度断言。已细分（D-30）。
  5. 接口顺序按验证结果调整，账号信息增加名片接口（D-32）。
- **观察**：真实的链接形态是 `b23.tv/mall-…`（两条不同的视频用了同一个链接）和 `b23.tv/cm-yy-…`、`b23.tv/cm-yaoyue-…`。
- **待确认**：名片接口是否可用；`is_word_search` 字段是否如预期；登录状态下 -352 是否消失。

### 2026-11-16 第四次：昨天能用的接口今天被拦

同一位创作者（UID 39627524），停在主页标签。

- **新走通的**：名片接口，读到了简介里的商务联系方式。账号层从 0 分变成 10 分，站外导流和机构也能明确判「无」。总分 40，区间 40–45。
- **新失败的**：`recArchivesByKeywords` 返回 HTTP 412，昨天它还是成功的。视频列表退到读主页上的链接：30 条里只有 19 条在 12 个月窗口内，不是最近投稿。
- **确认的**：误报「Akira」消失；商品短链的跳转地址确实是 `mall.bilibili.com`，附加信息里有 `goods_item_id`；视频编号片段的附加信息为空。按地址形态识别（D-30）成立。
- **发现的问题与修正**：
  1. 视频列表没有一条稳定的路径。新增「后台加载投稿页」，移除从未成功过的 `arc/search`（D-33）。
  2. 三条证据的标题是「207.1万265207:30」这样的乱码：读页面链接时把封面上的播放量和时长当成了标题。改为以详情接口的标题为准，并修正页面标题的挑选逻辑。
  3. 「充电专属」那条证据是碰巧命中的：封面角标的文字混在乱码标题里，规则恰好匹配。结论对，依据不对。改为读平台标记（D-34）。
  4. 降低请求密度：不再请求标签，并发从 3 降到 2，每条视频之间停顿（D-33）。
- **教训**：一次成功不等于可用。`recArchivesByKeywords` 昨天被我升为主路径，今天就被拦了。接口的验证结果要写「成功过几次、失败过几次」，不能只写「可用」。
- **待确认**：后台加载投稿页是否可行；`is_upower_exclusive` 字段是否存在；412 是否与请求量有关。

### 2026-11-16 第五次：第一份数据完整的报告

同一位创作者（UID 39627524），停在主页标签。

- **走通的**：后台加载投稿页成功，取到 30 条（2026-06-06 至 2026-11-12），与第三次验证时接口返回的时间范围一致，说明拿到的确实是最近投稿。充电专属字段确认存在，标出 6 条。证据标题全部正常。

## 模型调用

- 由侧边栏页面发起（内容脚本受页面跨域限制）。访问权限只在用户保存设置时按填写的地址单独申请（D-25）。
- 接口为 OpenAI 兼容格式，地址和 Key 在侧边栏底部的设置里配置，存浏览器本地存储。
- **只发送规则没有命中 A、B 档的视频**，合并为一次请求。
- 输出要过三道校验才成为证据：结论是枚举值；视频编号在本次输入里；引用是该视频原文的子串。任何一道不过，整条丢弃。模型无法产生 A、B 档证据。
- temperature 为 0；按「视频文本哈希 + 提示词版本 + 模型名」缓存到浏览器本地存储。
- 没有配置、调用失败、或模型没有判完所有待定视频时，C 档**整体**退回关键词，不混用两种口径（D-22）。报告里会说明。

## 侧边栏与内容脚本的通信

侧边栏通过长连接向内容脚本发请求（`src/messages.ts`），内容脚本回传进度和结果。页面在插件安装之前就已打开时内容脚本尚未注入，侧边栏连接失败后会补注入一次再重试。

报告属于发起分析时的创作者。用户之后切到别人的空间页，侧边栏会明确提示「下面的报告不是当前页面的创作者」。
