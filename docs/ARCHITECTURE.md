# 架构

## 数据流

```
B 站空间页
   │  内容脚本读取页面 + 请求公开接口
   ▼
CreatorSnapshot        创作者快照：账号信息 + 视频列表（标题、简介、标签、置顶评论）
   │  classify：规则（必有） + 模型（可选）
   ▼
Evidence[]             证据：哪条视频、哪一档、什么类型、原文引用、来源
   │  score：纯函数
   ▼
Report                 分数、区间、分档、子分、拆解、置信度
   │
   ▼
侧边栏界面
```

三个数据结构是模块之间唯一的接口。每一步只依赖上一步的输出。

## 模块

| 目录 | 职责 | 依赖浏览器 |
|---|---|---|
| `src/extract/` | 从 B 站页面和接口取数据，产出 `CreatorSnapshot` | 是 |
| `src/classify/` | `rules.ts` 关键词与正则；`llm.ts` 模型分类。产出 `Evidence[]` | 仅 `llm.ts` 需要网络 |
| `src/scoring/` | `score(snapshot, evidence) → Report`。参数全部在 `config.ts` | **否，纯函数** |
| `src/ui/` | 侧边栏：发起分析、进度、报告 | 是 |
| `src/pipeline.ts` | 侧边栏一侧的流程编排：提取 → 取样 → 分类 → 评分 | 是 |
| `entrypoints/` | 插件入口：后台脚本（只负责打开侧边栏）、内容脚本、侧边栏 | 是 |

评分引擎不依赖浏览器，是为了能用单元测试验证单调性、边界和可复现性，也方便校准时离线批量重算。

## 数据来源

提取在内容脚本里进行，请求带着空间页自己的上下文。接口为主、页面为辅（D-24）。

**下表的「验证结果」一列全部为未验证。** 开发环境直接请求 B 站接口会被风控拦截（D-17），接口路径和字段来自公开资料。每次分析时，提取层把每条路径是否走通记进 `CreatorSnapshot.sources`，报告底部的「数据来源自检」原样展示。在真实页面上跑过之后，把结果填回这张表。

| 数据 | 主路径 | 备用路径 | 验证结果 |
|---|---|---|---|
| 签名密钥 | `x/web-interface/nav`（未登录也返回） | 无；取不到则所有签名接口跳过 | 未验证 |
| 创作者 UID | 标签页地址（`src/extract/identify.ts`） | 无 | **已验证**：地址里 UID 前可能有语言前缀，见下方验证记录 |
| 昵称、简介、认证 | `x/space/wbi/acc/info`（需签名） | 昵称取页面标题；简介取页面描述信息；认证记为「未取到」 | 未验证 |
| 视频列表 | `x/space/wbi/arc/search`（需签名） | 页面上所有 `/video/BV…` 链接，不依赖类名 | 未验证 |
| 视频简介、发布时间 | `x/web-interface/view` | 列表接口里的简介（可能被截断） | 未验证 |
| 视频标签 | `x/tag/archive/tags` | 无 | 未验证 |
| 置顶评论 | `x/v2/reply/wbi/main`（需签名） | `x/v2/reply/main`，再退到 `x/v2/reply` | 未验证 |
| 评论里的商品链接 | 评论返回里的 `jump_url`，看附加信息是否带 goods 字段 | 无 | 未验证，字段名是推测 |
| 充电 | `acc/info` 返回里的 `elec.show_info.show` | 页面短文本里是否有「充电」 | 未验证，字段名是推测 |
| 小店、课程入口 | 页面短文本里是否有「小店 / 橱窗」「课堂 / 课程」 | 无 | 未验证 |

几个设计点：

- **WBI 签名**（`src/extract/wbi.ts`）是纯函数，用公开文档里的算例做了单元测试，算法本身是确认过的。
- **页面文字判断不依赖类名。** 收集页面上所有 8 个字以内的短文本，看有没有对应入口。只有认出了导航栏（「主页」「动态」「投稿」等）才敢说某个入口「无」，否则记为「未能检查」（D-13）。
- **限流**：单条视频的详情请求并发为 3，一次分析最多 30 条视频、约 90 个请求。
- **提取层只记录事实**，不做判断。例如置顶评论里的链接，提取层只记「这个片段是链接、平台是否标为商品」，算不算带货由分类层决定。

## 真实页面验证记录

每次在真实浏览器里验证后追加一条：看到了什么、与假设哪里不符、怎么改的。

### 2026-11-15 第一次：侧边栏认不出创作者

- **现象**：在 `space.bilibili.com/zh-Hans/447317111?spm_id_from=…`（未登录）打开侧边栏，提示「请在空间页打开本面板」；点「重新检测」没有任何变化。
- **原因**：识别规则假定域名后紧跟数字 UID。实际地址在 UID 前有一段语言前缀 `/zh-Hans/`。
- **修正**：
  1. 识别规则允许一段可选的语言前缀，并要求 UID 之后是路径分隔符或结尾，避免把路径里别处的数字当成 UID。
  2. 侧边栏和内容脚本原先各写了一份识别规则，合并为 `src/extract/identify.ts` 一处。
  3. 「重新检测」无论结果如何都显示带时间的反馈。
- **教训**：对页面地址和结构的假设在看到真实页面之前都不可靠。这次的问题发生在提取开始之前，所以数据来源自检没能帮上忙 —— 自检只覆盖了「提取过程」，没有覆盖「识别创作者」这一步。
- **从截图里额外确认的**：导航栏文字为「主页 / 动态 / 投稿 524 / 合集和系列 / 追番追剧」，与入口判断里用来认导航栏的词一致；个人简介里有「商务合作请联系vx：…」，与商务联系方式规则的写法一致。页头横幅图片里的「关注公众号」「小卖部」是图片上的字，读不到，属于已知局限。

## 模型调用

- 由侧边栏页面发起（内容脚本受页面跨域限制）。访问权限只在用户保存设置时按填写的地址单独申请（D-25）。
- 接口为 OpenAI 兼容格式，地址和 Key 在侧边栏底部的设置里配置，存浏览器本地存储。
- **只发送规则没有命中 A、B 档的视频**，合并为一次请求。
- 输出要过三道校验才成为证据：结论是枚举值；视频编号在本次输入里；引用是该视频原文的子串。任何一道不过，整条丢弃。模型无法产生 A、B 档证据。
- temperature 为 0；按「视频文本哈希 + 提示词版本 + 模型名」缓存到浏览器本地存储。
- 没有配置、调用失败、或模型没有判完所有待定视频时，C 档**整体**退回关键词，不混用两种口径（D-22）。报告里会说明。

## 侧边栏与内容脚本的通信

侧边栏通过长连接向内容脚本发请求（`src/messages.ts`），内容脚本回传进度和结果。页面在插件安装之前就已打开时内容脚本尚未注入，侧边栏连接失败后会补注入一次再重试。

报告属于发起分析时的创作者。用户之后切到别人的空间页，侧边栏会明确提示「下面的报告不是当前页面的创作者」。
